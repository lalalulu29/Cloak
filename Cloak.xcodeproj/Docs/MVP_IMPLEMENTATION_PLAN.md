# Cloak — MVP Implementation Plan

## 1. Цель MVP
Подтвердить, что пользователи готовы возвращаться ежедневно к циклу:
«утром запомнил -> вечером проверил».

## 2. Scope MVP
- Режим только «Числа».
- Одно число в день.
- Утренний показ числа.
- Вечерняя проверка с ограничением по времени (после времени окончания дня).
- Локальные уведомления: утро, день, вечер.
- История и базовая статистика.
- Базовые настройки расписания, частоты напоминаний и длины числа.

## 3. Реализованный статус (на 17 апреля 2026)
## Готово
- Daily lifecycle и статусы дня (`notRevealed`, `awaitingAnswer`, `completed`).
- Модель `DailyChallenge` + персистентность в SwiftData.
- Генерация числа дня и стабильность числа в пределах дня.
- Утренний flow показа числа (без повторного раскрытия).
- Вечерний ввод и проверка ответа (`correct` / `wrong`).
- Автомаркировка пропусков (`missed`) для незавершенных прошлых дней.
- История результатов.
- Базовая статистика (`currentStreak`, `bestStreak`, `accuracy`, `totalAnswered`).
- Onboarding первого запуска с параметрами:
  - начало дня;
  - конец дня;
  - частота дневных напоминаний (уровни сложности).
- Запрос разрешения уведомлений перенесен в первый запуск.
- В настройках отображается статус уведомлений.
- Планировщик уведомлений и пересоздание расписания при изменениях.
- Настройка длины числа (3...8, дефолт 4).
- Применение длины к ближайшему не начатому периоду.

## Частично
- Edge-cases времени/таймзоны требуют отдельного QA-прохода.

## 4. Текущие пользовательские сценарии
1. Новый пользователь
- Проходит onboarding.
- Задает параметры дня и частоту напоминаний.
- Получает запрос разрешения уведомлений.
- Начинает дневной цикл.

2. Обычный день
- Утром открывает число.
- Днем получает напоминания.
- Вечером (после настроенного времени) вводит число и видит результат.

3. Пропуск
- Если ответа нет до следующего дня, запись помечается как `missed`.

## 5. Модель данных (факт)
## DailyChallenge
- `dayStart`
- `value`
- `length`
- `shownAt`
- `answeredAt`
- `userAnswer`
- `result` (`correct` / `wrong` / `missed`)

## Settings (через AppStorage)
- `morningHour`, `morningMinute`
- `eveningHour`, `eveningMinute`
- `daytimeReminderCount` (1...5)
- `numberLength` (3...8)
- `hasSeenOnboarding`

## 6. Экраны (факт)
- Today: статус дня, утренний CTA, вечерняя проверка.
- History: список дней и статусов.
- Settings: статус уведомлений, время начала/конца дня, частота напоминаний, длина числа.
- Onboarding: ввод базовых параметров при первом запуске.

## 7. Следующий фокус
- QA edge-cases (полночь, смена часового пояса, сценарии с отключенными уведомлениями).
- Полировка текстов и пустых состояний.
- Подготовка к адаптивной длине как MVP+.
